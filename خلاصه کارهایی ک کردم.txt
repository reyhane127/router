   │
   ├── LINKS
   │     ├── wan  → eth0
   │     ├── wifi → wlan0
   │     └── lte  → wwan0
   │
   └── PROFILE
         ├── home
         └── industrial

LinkMonitor
   │
   ├── Ping       → per interface ✅
   ├── Latency    → ✅
   ├── Packet Loss→ ✅
   ├── DNS        → عمومی ✅
   └── HTTP       → per interface ✅

DecisionEngine → هنوز ساخته نشده
RouteManager   → هنوز ساخته نشده


برای لینک مانیتور:
✅ Ping
✅ Latency
✅ Packet Loss
✅ DNS
✅ HTTP
✅ بررسی هر interface به‌صورت جداگانه
✅ برگرداندن یک نتیجه‌ی استاندارد از check_link()
✅ بدون دخالت در Routing و Failover

و config.py هم خوب تفکیک شده:

✅ Profileهای home و industrial
✅ اولویت لینک‌ها
✅ interface هر لینک
✅ targetهای health check
✅ thresholdهای failure/recovery
✅ interval


check_dns() فعلاً interface-specific نیست.
FAILURE_THRESHOLD و RECOVERY_THRESHOLD هنوز استفاده نشده‌اند؛ که کاملاً طبیعی است چون بخش Failover را هنوز ننوشتی.

#network_manager:

همچین کاری میکنه:

برو وضعیت WAN را بگیر
برو وضعیت WiFi را بگیر
برو وضعیت LTE را بگیر

        ↓

همه نتایج را بده به DecisionEngine

        ↓

DecisionEngine می‌گوید WAN

        ↓

WAN را بده به RouteManager



apply_decision: منطق 

selected_link == None؟
        │
       بله ──→ هیچ تغییری نده → False
        │
       خیر
        ↓
selected_link == current_link؟
        │
       بله ──→ هیچ تغییری نده → False
        │
       خیر
        ↓
RouteManager.apply_link()
        ↓
موفق؟
   │          │
  بله        خیر
   │          │
current_link  current_link
= selected    بدون تغییر
   │          │
 True        False
